- **Employee** — uses CORPUS / EBV-Portal daily, gets help in place, by voice or proactively.

## Non-functional

- **Privacy:** filter in the extension before sending (UI labels yes, user content/values no); pseudonymous ids; admin views only aggregates with **min. group size 5**; no individual performance evaluation (works council, § 87 (1) 6 BetrVG). EBV-Portal additionally needs consent (TDDDG) — exists there.
- **Data:** test data only. CORPUS runs locally on the demo laptop with sample data and a test login; **vehicle pages are excluded** (real fleet data) — enforced by the app policy (R-ORG-6, D-27), not by the presenter.
- **Gemini:** paid key only (no training on our data). EU residency would require Vertex AI (open, see decisions).
- **Reliability:** every demoed feature works 20 of 20 runs, otherwise it's cut.
- **Current validation instruction:** the user forbids tests. Extension completion means code implemented and statically checked (typecheck, lint, build); browser/Gemini execution and 20/20 reliability have not been established.
- **Cost/abuse:** bounded agent loops (`isStepCount ≤ 10`), one short Live session per question, no always-on streaming.
- **Latency target:** highlight visible < 3 s after question/trigger.

## Demo script (3 min)

1. Someone searches CORPUS manually for a key → Lotse speaks up and points to the right place.
2. Voice question → Lotse shows step by step how to create something.
3. Same in a second, known app without setup (candidate: EBV-Portal, local, test data).
4. Lotse creates a task in CORPUS by itself.
5. (Pitch) Dashboard: pain points → training suggestions.
